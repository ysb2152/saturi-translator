## B. 권한 정리 (Play 심사 마찰 — 실제 발견)

AndroidManifest에 앱이 **쓰지 않는데 라이브러리(@siteed/expo-audio-studio)가 끌어온 민감 권한**이 있음:

| 권한 | 문제 | 조치 |
|---|---|---|
| `SYSTEM_ALERT_WINDOW` | "다른 앱 위에 그리기" 민감권한. 앱 미사용 | ⚠️ 제거 권장(config plugin `tools:node="remove"`) |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Android 14+ **전경 서비스 유형 선언** 필요(미선언 시 반려). 앱은 전경 녹음만 함 | ⚠️ 제거 검토 또는 Play Console에 전경서비스 사유 제출 |
| `FOREGROUND_SERVICE` | 위와 동일 맥락 | ⚠️ 제거 가능한지 검증 |
| `RECORD_AUDIO`, `INTERNET`, `VIBRATE`, `MODIFY_AUDIO_SETTINGS` | 정당(녹음·모델 다운로드·햅틱) | ✅ 유지 |
| `READ/WRITE_EXTERNAL_STORAGE` (maxSdk 32) | 레거시, 무해 | ✅ 유지 |

> 검증 필요: 위 전경서비스 권한을 제거해도 녹음이 정상인지 실기기 확인. 제거 가능하면 심사·데이터안전 모두 깔끔해짐.

## E. 앱 완성도 — 코드에서 발견한 부족한 점

우선순위 순. (파일: `mobile/App.js`, `src/modelDownload.js`, `src/ondevicePipeline.js`, `src/ondeviceConverter.js`)

### E1. 다운로드 견고성 (중요)
- **재시도 버튼 없음**: 다운로드/로드 실패 시 에러 문구만 뜨고, 사용자가 **앱을 완전히 껐다 켜야** 재시도됨(`App.js` mount effect 1회성). → "다시 시도" 버튼 필요.
- **진짜 이어받기 아님**: `createDownloadResumable`를 쓰지만 resume 토큰을 앱 재시작 사이에 저장 안 함. 앱이 다운로드 중 죽으면 그 파일(최대 176MB)을 **처음부터** 다시 받음. 존재 체크가 <90%면 미완으로 보고 재다운로드. → resumeData 저장 또는 최소한 부분파일 정리.
- **무결성 검증 없음**: 크기 ≥기대치의 90%만 확인(`present()`), 체크섬 없음. 손상/truncate된 200 응답이 통과하면 모델 로드가 알 수 없는 에러로 크래시. → SHA256 또는 정확 크기 검증.
- **셀룰러 경고 없음**: 첫 실행 490MB를 Wi-Fi/데이터 구분 없이 받음. → Wi-Fi 권장/데이터 경고.

### E2. 저장공간 관리
- **녹음 파일 누적**: 매 녹음마다 WAV가 앱 내부(`files/`)에 생성되나 **삭제 로직 없음**(`stopAndSend`에서 처리 후 방치). 장기적으로 용량 증가. → 처리 후 임시 WAV 삭제.

### E3. 접근성 (포트폴리오 감점 요소)
- 마이크 `Pressable`에 `accessibilityLabel`/`accessibilityRole`/`accessibilityState` 없음. 스크린리더 사용자가 버튼 용도·상태를 못 읽음. → 라벨 추가.
- 결과 텍스트가 **선택/복사 불가**(`Text` 기본). 표준어 결과를 복사할 수 없음. → `selectable` 또는 복사 버튼.

### E4. UX 다듬기
- **녹음 취소 불가**: 녹음 시작 후 무조건 정지→변환. 실수 녹음을 버릴 방법 없음.
- **녹음 길이 무제한**: 아주 긴 발화 시 처리 지연·메모리 부담. → 최대 길이(예 30초) 가이드/컷.
- **모델 로드 단계 진행률 없음**: 다운로드는 %가 있지만 로드는 왕복 애니메이션만(수 초~십수 초 무표시).

### E5. 모델 버전 관리
- 다운로드 파일 목록이 고정(`models-v1`). 나중에 모델을 개선해 `models-v2`를 올려도 앱이 **재다운로드할 신호가 없음**(기존 파일 있으면 통과). → 버전 태그/매니페스트 기반 갱신 로직(지금은 불필요, 향후 과제).
